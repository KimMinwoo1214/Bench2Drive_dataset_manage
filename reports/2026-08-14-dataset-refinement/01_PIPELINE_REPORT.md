## 1. 문제 1 — 전문가가 사고를 낸 클립

### 1.1 왜 걸러야 하나

CARLA leaderboard 전문가는 충돌을 내도 **주행을 계속한다.** 그래서 사고가
클립 끝이 아니라 중간에 있고, 그대로 학습하면 모델이 그 주행을 정답으로 배운다.

문제는 **데이터에 충돌 정답이 없다는 것**이다. 클립에는
`anno / camera / expert_assessment / lidar / radar` 뿐이고 CARLA 충돌 센서
기록이 없다. **annotation에서 추론해야 했다.**

### 1.2 접촉 찾기 (1단계)

모든 프레임에서 ego 박스와 주변 actor 박스의 교차를 계산한다.

```
접촉 = (BEV 교차면적 > 0  AND  z축 겹침 > 0)          ← 실제 겹침
       OR (z축 겹침 > 0  AND  BEV 간격 ≤ 0.10 m)      ← 아슬아슬한 근접
```

- **회전 반영**: 축 정렬이 아니라 차량 yaw를 적용한 사각형끼리 교차
- **z축 확인**: 고가도로 위아래로 지나가는 차가 위에서 보면 겹치는 것을 배제
- **간격 0.10m도 접촉**: 10Hz라 충돌이 두 샘플 사이에 끝나면 겹침이 안 잡힌다
- 대상은 `vehicle` / `pedestrian` / `bicycle` 셋뿐

> 결과: **접촉 런 296건 / 237 클립**

### 1.3 진짜 충돌인가 (2단계)

핵심 원리:

> **급제동은 ego만 변한다. 주차차량과 박스가 겹치는 건 둘 다 안 변한다.
> 충돌은 둘 다 변한다.**

접촉 런 앞뒤 4프레임에서 ego와 상대 **각각**의 속도·방향 변화를 잰다.
한 프레임에 **15 m/s 넘는 변화는 제외**한다 — 물리적으로 불가능(150 m/s²)하고
실제로는 actor 스폰 프레임의 로그 결함이다. (이걸 안 걸렀을 때
`YieldToEmergencyVehicle` 9개가 상대 Δv 25 m/s로 상위를 차지했다.)

| 근거 코드 | 조건 | 뜻 |
|---|---|---|
| `EGO_IMPULSE_BEYOND_BRAKING` | ego Δv ≥ 3.0 m/s (=30 m/s²) | 이 데이터 제동은 26 m/s²에서 포화. **브레이크로는 불가능** |
| `BOTH_BODIES_REACT` | 양쪽 다 Δv ≥ 1.0 또는 Δyaw ≥ 0.05 | 두 물체가 함께 튕김 |
| `ACTOR_ONLY_REACTION` | 상대만 반응 + 실제 겹침 | ego가 들이받음 |
| `EPISODE_ENDS_AT_CONTACT` | 접촉 후 잔여 ≤ 2 프레임 | 충돌로 주행 종료 |
| `DEEP_PENETRATION` | 관통 ≥ 0.30 m | 보조 |

### 1.4 등급 — 여기가 핵심이다

```python
if max(ego_speed, actor_speed) < 1.0:            → D. 정지 겹침 (충돌 아님)
elif 상대가 pedestrian/bicycle and 실제겹침 > 0:  → A. VRU 충돌
elif EGO_IMPULSE_BEYOND_BRAKING:                 → A. 충격량
elif 근거 코드가 1개 이상:                         → B. 의심
elif 실제겹침 > 0 and ego ≥ 2.0 and 관통 ≥ 0.10:  → C. 차량 접촉
else:                                            → E. 경미
```

**왜 보행자·자전거는 반응을 안 따지는가.** 사람을 치면 차가 안 느려진다.
질량이 무시할 수준이라 ego Δv가 0에 가깝다. "두 물체가 함께 반응"은
차량-차량엔 맞지만 **VRU엔 구조적으로 틀렸다.** 실제로 이 규칙 전에는
`DynamicObjectCrossing` 접촉 5건이 **전부 "반응없음"**으로 빠져 우선 목록에
0개였다.

**왜 차량은 반응이 없어도 보는가.** 옆에서 긁히면 속도가 안 줄어든다.
측면 스침은 어떤 반응 신호도 남기지 않는다. 확인된 사례:
`LaneChange_Town12_Route17604` — 시속 54km, ego Δv **0.00**, 영상으로는
명백한 측면 접촉.

## 2. 문제 2 — 신호등 위치가 한 칸씩 밀려 있다

### 2.1 원인

수집 코드(`tools/data_collect.py`)가 actor 목록과
`world.get_level_bbs(TrafficLight)` 목록을 **2D 최근접 greedy**로 붙인다.
그런데 CARLA 마스트형 신호등은 **폴(actor 원점)이 모퉁이에 있고, 그 폴이
통제하는 등(head)은 교차로 건너편**에 매달려 있다. 따라서 actor 원점에 가장
가까운 head는 **항상 옆 접근로의 것**이고, 매칭이 교차로 단위로 한 칸씩 회전한다.

결과적으로 한 엔트리 안에 **두 actor의 정보가 섞인다**:

| 필드 | 출처 | 상태 |
|---|---|---|
| `location` `rotation` `center` `extent` `road_id` `lane_id` `section_id` | level bbox | **틀림 (한 칸 밀림)** |
| `id` `state` `distance` `trigger_volume_location` `trigger_volume_extent` | actor | 정확 |
| `trigger_volume_rotation` | 둘의 합 | **오염** |

### 2.2 복구 로직

> 어떤 신호등의 head는 자기 trigger volume의 **건너편**에 있어야 한다.
> 교차로 중심 기준으로 `head_angle ≈ tv_angle + 180°`.

이 조건을 비용 행렬로 두고 교차로 단위로 **Hungarian**을 푼다.

```
1. trigger volume 근접(30m)으로 교차로 그룹핑
2. 그룹이 이미 정상 대역이면  →  절대 건드리지 않는다   (안전장치)
3. Hungarian 풀이
4. 재배정 결과가 그룹 전원 정상 대역에 들어오면  →  수용
   아니면  →  기각 (원본 유지)
5. 전 프레임의 결과를 월드 좌표 키로 투표 → 전역 합의
6. 합의를 전 프레임에 적용
```

**`distance` 기반 재배정은 쓰면 안 된다.** 수집 코드의 greedy가 바로 그 값을
최소화했으므로 **같은 오답을 재생산**한다.

### 2.3 검증이 자기채점이 아닌 이유

배정이 맞으면 head가 자기 trigger volume 쪽을 향하므로 그 각도(**facing
error**)가 **80~100°**로 모인다. 한 칸 밀린 배정은 그 근처에 올 수 없다
(≈18°에 봉우리가 생긴다). **이 값은 복구 결과와 무관하게 측정된다.**

### 2.4 결과

| | 값 |
|---|---:|
| 전체 annotation 프레임 | 324,566 |
| 신호등 엔트리 | 1,119,119 |
| **재배정된 엔트리** | **186,592** |
| bbox가 바뀐 프레임 | 56,539 |
| **배정 정상률** | **57.7% → 75.4%** |

`fix_report_v3/facing_error_before_after.png`에서 수정 전 **18° 봉우리**가
수정 후 사라지는 것이 보인다.

### 2.5 진행 중 발견한 결함 — 검토자가 잡았다

검토자가 렌더 프레임에서 **"ego를 마주보는 신호등에 박스가 안 붙는다"**고
지적했다. 확인해보니 그 클립은 신호등 7개 전부 수정이 안 돼 있었고, 원인은
수용 조건의 순서였다.

```python
if resid > MAX_ANG_RESID: continue          # ← 대리 지표가 먼저 기각
if not band_ok(after): continue             # ← 결과를 직접 검증하는 강한 검사
```

`resid`(평균 각도 잔차)는 **대리 지표**이고 `band_ok(after)`가 같은 것을
**직접 확인**하는데, 약한 검사가 먼저 걸러버렸다. 그 클립의 한 그룹은
**잔차 35.3 vs 한계 35.0 — 0.3° 차이로** 기각돼 있었고, 재배정하면 facing이
18/20/96 → **82/82/83**으로 셋 다 정상이 되는 케이스였다.

**측정**: 표본 200클립에서 결과 검증은 통과하는데 잔차가 막은 엔트리가
**1,914개**(수용분 2,870의 67%). 승인을 받아 `resid` 게이트를 제거했다.

**재실행 결과**: 재배정 163,861 → **186,592** (+22,731), 정상률 73.8% →
**75.4%**. 새로 문제가 생긴 클립은 **0개**.

## 3. 문제 3 — 어느 신호등이 ego를 통제하는가

### 3.1 로직

ego 궤적이 어느 신호등의 **trigger volume을 통과하는지**로 판정한다.
`trigger_volume_location`은 actor에서 온 값이라 **치환 손상을 받지 않는다.**

```
1. 궤적 구간이 trigger volume과 교차하는가
2. ego 진행 방향과 신호등 통제 방향의 각도차가 임계 이내인가
3. 그 판정이 최소 프레임 수 이상 연속되는가
4. bbox 배정이 검증됐는가 (2.3의 facing error)

전부 만족  →  AUTO_FIX (자동 적용)
하나라도 미달  →  REVIEW (원본 유지, 사람에게 올림)
```

### 3.2 결과

| 변경 방향 | 엔트리 |
|---|---:|
| `false` → `true` | **17,067** |
| `true` → `false` | 98 |
| 변경된 클립 | 315 |

압도적으로 **"영향 없음"으로 잘못 적혀 있던 것을 켠 것**이다. 원본이 신호등을
놓치고 있었다는 뜻이다.

### 3.3 전수 외부 검증 — 정차 후 재출발

**이 검증은 검토자의 지적에서 나왔다.** "모델한테 넘길 때 정차 후 재출발이
중요한데, 다시 출발할 때는 초록불이어야 가는 거잖아."

> ego가 신호에 서 있다가 **출발하는 순간 그 신호등은 초록이어야 한다.**

relabel은 **ego 속도를 전혀 읽지 않았다.** 그래서 이 일치는 자기채점이 아니고,
표본이 아니라 **1,300 클립 전수**로 잴 수 있다.

**측정 방법**
```
정차 = 속도 ≤ 0.10 m/s 가 10프레임(1초) 이상 지속
출발 = 그 뒤 30프레임 안에 속도 ≥ 1.00 m/s 도달
판정 = 출발 프레임에서 affects_ego 신호등의 state
```

**주의해야 했던 것 두 가지.** 출발은 점진적이라(0.1 → 0.18 → 0.28 → 1.5) 두
문턱을 한 프레임에 통과할 것을 기대하면 **사건이 0건 나온다.** 그리고 출발
전후 창의 앞쪽부터 훑으면 **출발 직전의 빨간불**을 집게 되므로 출발 프레임
자체를 봐야 한다.

**분모도 걸러야 했다.** `AccidentTwoWays`는 사고 차량 우회를 위해 10초씩
정차하는데, 그 출발은 신호와 무관하다. 신호등까지의 `distance`(actor 값)로
분리했다.

**결과 (정지선 40m 이내 = 진짜 신호 대기)**

| | original | corrected | 차이 |
|---|---:|---:|---:|
| 정차→출발 사건 | 209 | **236** | **+27** |
| 출발 시 GREEN | 201 | **227** | +26 |
| **일치율** | **96.2%** | **96.2%** | **0.0%p** |

> **일치율은 유지한 채 진짜 신호 대기 사건을 27건(+13%) 더 찾아냈다.**
> 원본이 놓치고 있던 신호등을 켰다는 뜻이고, 그것이 잘못된 라벨을 늘리지
> 않았다는 뜻이다.

참고로 전체(거리 무관)로는 222 → 275건, 92.8% → 87.6%다. 떨어지는 부분은
60m 밖이고, 그건 장애물 정차가 섞인 구간이라 이 지표가 성립하지 않는다.

### 3.4 육안 검증

| 대상 | 이미지 |
|---|---:|
| `affects_ego`가 **실제로 바뀐** 프레임 (25개 시나리오 계열 × 30클립) | **360장** |
| 도구가 판단을 **보류한** 클립 85개 | **932장** |

각 장은 위=원본 anno, 아래=수정본 anno, **같은 프레임**이다.
확인된 대표 사례: `SignalizedJunctionLeftTurn_Town04_Route173` 프레임 64 —
정면 mast arm의 `TL 14203`이 `GREEN UNAFFECTED` → `GREEN AFFECTS`로 켜졌고,
bbox 복구로 박스도 정면 mast arm 위에 정확히 올라갔다.

## 4. 한계 — 무엇을 못 고쳤나

### 4.1 rotation(bbox 배정) 한계 — **어쩔 수 없다**

복구 규칙이 "head는 교차로 **건너편**에 있다"인데, **그 조건이 배정을 유일하게
정하려면 교차로에 신호등이 충분히 있어야 한다.**

| 남은 미수정 엔트리가 속한 교차로 | 엔트리 |
|---|---:|
| 신호등 **1개** | 4,745 |
| 신호등 **2개** | 607 |
| 신호등 3개 (기하가 안 맞음) | 3,631 |

- **1~2개인 곳**: 배정을 결정할 정보 자체가 없다. T자 교차로가 대표적이다.
- **3개인데 안 되는 곳**: 재배정하면 오히려 나빠진다. 실측 사례에서
  facing이 86/34/95 → **162/126/127**로 악화됐다. 기각이 옳다.

**이건 임계값을 더 풀어서 해결되는 문제가 아니다.** 2.5절에서 대리 지표를
걷어냈을 때 걷을 수 있는 건 거의 다 걷었고(+22,731), 그러고도 review 클립은
85 → 83으로 2개만 줄었다. **남은 것은 구조적 한계다.**

**영향 범위**: 전체 신호등 엔트리 1,119,119개 중 ego에 영향을 주는 것은
74,779개(6.7%)뿐이고, 그중 배정 미검증이면서 각도가 안 맞는 것은
**8,983개 — 전체의 0.80%**, 클립으로는 **50개**에 몰려 있다.
**재배정한 14,662개 중 각도가 안 맞는 것은 0개다.**

**완화 요인**: `affects_ego` 판정은 오염되지 않은 `trigger_volume_location`으로
하므로, **박스 위치가 틀린 것과 통제 판정이 틀린 것은 별개다.** 그리고 이런
엔트리는 `bbox_not_verified` / `confidence=review`로 **표시되지 조용히
통과하지 않는다.**

### 4.2 `affects_ego` 한계

**독립 검증이 부분적이다.** 3.3의 정차-재출발 지표는 강력하지만 **정차가
일어난 사건에만** 적용된다 — 신호를 통과만 하고 서지 않은 구간은 이 지표로
검증되지 않는다. 그 부분은 육안 표본(360장)에 의존한다.

**보류된 것**: 85 → **83 클립, 7,546 프레임(전체의 2.3%)**. 사유는
`bbox_not_verified`(배정 미검증)와
`existing_label_without_crossing_evidence`(원본이 지목한 신호등을 ego 궤적이
통과한 적 없음) 두 가지가 대부분이다. **이 프레임들은 원본 값 그대로 저장됐고**,
사람 승인은 "그대로 두는 것에 동의한다"는 기록이다.

### 4.3 depth

Weak 329개 중 canonical 경로의 depth 284개가 누락돼 있으나 서버 권한이 없어
직접 보완 불가. **ailab 소유 symlink overlay**(`inputs/weak_root_patched_v1`)로
우회했고 canonical은 건드리지 않았다. dataset owner가
`phase2_5_logs/run_phase2_5c_depth_apply.sh`를 sudo로 실행하면 실제 보완된다.

## 5. 성능 — 파이프라인이 완주 가능해진 과정

relabel 1,300 클립이 처음엔 **2.3시간**으로 추정됐고, 두 결함을 고쳐 **35분**이
됐다.

| 병목 | 원인 | 조치 | 효과 |
|---|---|---|---|
| bbox consensus | 24코어에서 **0.67코어**만 사용 | 3패스 전부 클립 단위 독립이고 합의는 리듀스 → 12워커 병렬화 | 45분 → **4분** |
| 클립 루프 | **103MB 진단 CSV를 클립마다 재파싱** (977회 ≈ 100GB) | 한 번만 읽어 클립별로 그룹핑 | 3.5초 → **0.004초/클립** |

두 번째는 **병렬화로 못 고친다** — 12코어로 나눠도 100GB 파싱은 그대로다.

병렬화가 결과를 바꾸지 않음을 검증했다: 24클립에서 **출력 annotation 9,190개
바이트 단위 동일**, 진단 CSV 2종 동일, 통계 동일. 동점 처리가 워커 순서에
의존하지 않도록 tie-break도 결정적으로 고쳤다.
